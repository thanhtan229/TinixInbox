Reviewed on 2026-09-28 against `PLAN_TinixInbox_V2.md`. These checkpoints distinguish code present in the local implementation from real provider acceptance evidence. This review includes a live synthetic Tinix ↔ Chatwoot CE v4.18.0 REST contract run; callback delivery into Tinix and real provider delivery remain separate gates. The latest local runtime check confirms Docker/Chatwoot and Tinix `/health` are healthy, but `/api/connections` contains only the synthetic connection. The health response reports Gemini as configured; that flag does not prove the key is valid or generation works.

These documents do not prove that Tinix has an approved app or seller/OA account.

## Phase 0 — Repository audit and Chatwoot POC

**Status: READY WITH LIMITATIONS.** The local Chatwoot POC services are pinned to CE v4.18.0. Tinix now has a callback-only loopback relay (port 3183) and a temporary Cloudflare Quick Tunnel launcher aimed at that relay; two relay tests confirm other paths are refused and raw body/signature headers are preserved. Neither relay nor tunnel was started during this run. A live signed callback to Tinix, stable production HTTPS topology, and delivery through a real approved channel remain open.

## Phase 1 — Inbox core and Chatwoot provider

**Status: IMPLEMENTED FOR SYNTHETIC FLOWS; LIVE CHATWOOT REST ACCEPTANCE PASSED; CHATWOOT CALLBACK TOPOLOGY OPEN.** Inbound claims are acquired before Chatwoot side effects; ambiguous outcomes remain `unknown` and are listed for reconciliation instead of being blindly replayed. The live POC uses the real Tinix `InboundService` and `ChatwootConversationProvider` with Chatwoot CE v4.18.0. It confirms mapped incoming messages, duplicate suppression, one public synthetic outgoing message, assignment, and status changes. The HTTP callback boundary requires JSON content type and rejects malformed/non-object payloads before ACK. The HTTP-level E2E sends signed callbacks through the real server route, verifies durable event recording and outbox dispatch, resends a duplicate and measures one send, and exercises both AI-projection-before-callback and callback-before-AI-projection orderings while preserving the real outbox link and provenance. The Chatwoot container itself has not delivered a callback to Tinix; SafeFetch blocks local URLs and stable/public HTTPS callback topology still needs approval and live POC validation.

## Phase 3 — AI and human handoff

**Status: PARTIAL / LIVE PROVIDER NOT VERIFIED.** `GeminiClient` is wired to the inbound agent router and supports Function Calling. Missing keys and Gemini failures fail closed without sending canned replies. Handoff state uses version checks to prevent a send after human takeover. The standard AI reply test exercises `GeminiClient → InboxAgentRouter → ConversationProvider` with a deterministic fake HTTP response and checks the prompt, outgoing reply and AI provenance; the handoff race test verifies takeover cancellation. Review also found that AI message links previously stored a random placeholder `outbox_id` before Chatwoot's callback created the real outbox row. AI now leaves that field empty, and the callback attaches the durable outbox ID to the existing AI message projection; the HTTP callback E2E verifies it preserves AI provenance and points at the actual sent outbox row. The local `/health` response reports `aiConfigured: true`, but Gemini key validity and generation against Google's service remain unverified. UI takeover is available; resume still needs a full live handoff test.

## Phase 5 — Native Tinix Inbox UI V1

**Status: PARTIAL.** Native UI provides a 3-column workspace with channel filters, Tinix delivery states, older-message pagination, scroll preservation, SSE updates for messages/delivery/handoff, and six-second polling fallback. The UI opens/resolves conversations through a validated Tinix API; Chatwoot confirmation precedes updating Tinix's status projection. AI resume is disabled in the UI and rejected by the API when no Gemini key is configured. The context panel loads inbox-eligible agents through the ConversationProvider, validates membership again on assignment, and exposes only sanitized `{id, name}` values. The conversation list now projects contact names and assignees from Chatwoot's paginated list endpoint, grouped by inbox with a 10-second cache invalidated after assignment; search and the active header use the contact name. Tinix does not expose Chatwoot thumbnail URLs. On the pinned local CE runtime, unassigned conversations omit `meta.assignee`; read-only GET detail calls showed the same omission, so the Tinix projection maps that shape to unassigned. API failure degrades the assignee label without hiding conversations. Provider mapping, workspace checks, token/thumbnail redaction, cache behavior, and assignment invalidation have automated tests. After restart, the live API returned contact names and `assignee: null` for both mapped conversations; browser review confirmed those names in the list/header, “Chưa giao,” and the eligible POC agent in the selected conversation's assignment panel. Connection controls now pause/resume a channel with an additive SQLite field to restore its prior state; paused channels reject public sends and webhook intake, retain queued outbox work, and resume dispatch after re-enable. Lifecycle transitions, legacy-database migration, API validation, disabled sends, and outbox pause/race handling have automated tests. Existing Chatwoot message attachments now render through a Tinix proxy that restricts downloads to the configured Chatwoot origin, caps size at 12 MB, inlines an explicit media MIME allowlist, and downloads other files as octet-stream; provider URLs are kept out of the browser DTO. Attachment mapping, proxy headers, origin/redirect rejection, and size limits have tests. Uploading/sending attachments remains unavailable, and cross-origin object-storage redirects need an explicit host allowlist before support. After restart, `/health` returned `ok`, the UI returned HTTP 200, and the public connections/conversation responses contained no credential fields. Operator actions still lack Tinix authentication/RBAC. Unread behavior and formal browser E2E acceptance remain incomplete. The attachment composer control is disabled until a secure upload-to-provider flow is implemented.

## Phase 8 — Business tools / n8n

**Status: PARTIAL.** The tool registry is wired to Gemini Function Calling and can call configured n8n webhook paths with a bearer token. CRM lead creation and internal notifications now send a deterministic `Idempotency-Key` derived from the stable inbound message correlation and tool name; retrying a write for the same message uses the same key, and an uncorrelated write is refused. Fake local customer/order data is exposed only when `BUSINESS_TOOLS_DEMO_MODE=true` outside production, and local bootstrap defaults demo mode off. Review tests cover correlation propagation, repeated-write key stability, distinct tool actions, and refusal without correlation. The receiving n8n workflow must persist/dedupe this key; no real n8n contract/authenticated workflow E2E has verified that behavior. The latest full build passes typecheck and 94/94 tests.

## Phase 9 — Production hardening

**Status: PARTIAL.** Unit/E2E tests cover outbox claims, unknown outcomes, restart recovery, tenant isolation, webhook persistence, callback security, and bounded retry. A stress test submits 100 simultaneous duplicate signed callbacks while 16 outbox workers compete; it records all 100 callback receipts, creates one outbox row, and measures exactly one synthetic send. Until Tinix auth/RBAC is implemented, production startup now rejects non-loopback binds; tests cover loopback acceptance and network-bind rejection. Credentials and callback secrets use AES-256-GCM key IDs with startup rewrap support. `npm run drill:backup-restore` snapshots the configured SQLite database, restores it into an isolated temporary copy, checks core row counts and SQLite integrity, then rotates and decrypts every copied connection secret using a fresh ephemeral key. The drill passed against the current local database (1 connection, 2 conversations, 12 messages, 3 outbox rows); it did not modify the active database or deployment keys. Remaining work includes Tinix authentication/RBAC, authenticated dead-letter/unknown-send tools, retention, monitoring/alerts, broader callback/reconciliation load and chaos tests, and a Chatwoot upgrade contract suite.

## Review result

The local synthetic core, Gemini wiring, callback-only relay, SSE updates, and basic open/resolve UI are implemented. The backup/restore and secret-rotation mechanics now pass an isolated drill. The complete V2 plan is not LGTM: Chatwoot callback/outbox live acceptance, real AI configuration, provider approvals/accounts, authenticated n8n and write idempotency, operator RBAC, and production operations remain open. The local Quick Tunnel is temporary and was not started.
